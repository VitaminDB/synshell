# План реализации: съёмочная группа агентов (видеоредактор + служба)

Основа — «Съёмочная группа агентов, вторая версия». Исполнители: **synshell-d3** — видеоредактор (syn-video-editor, syn-assist, syngui), **synaptix-uncensored** — служба (synaptix + synaptixd: парковка контекста). Пока идёт текущий прогон фильма: окно редактора и службу не перезапускать, видеокарту не занимать, ставить только после прогона.

## Этап 1. Роли, конвейер и брифы (synshell-d3)

1.1. **Описание ролей** (данные, не код): id, название, навыки роли, документы-владения, шаги конвейера, роль-проверяющий для каждого типа результата. Роли: режиссёр, сценарист, скрипт-супервайзер, художник-постановщик, оператор, звукорежиссёр, монтажёр (композитор — внутри звука на первом этапе).
1.2. **Навыки по ролям:** разрезать текущие (screenplay, video-story, minimax-h3, qwen-image, drama3, montage, music-for-video, russian-speech) на ролевые наборы. Каждая роль грузит только свои. Только общие правила.
1.3. **Машина состояний сцены** в коде (продолжение текущего «сцена за сценой»): статусы оригинал → сценарий → сверка → ассеты → озвучка → раскадровка → съёмка → проверка → склейка → готово. У каждого статуса роль-автор и роль-проверяющий. Переходы открывают существующие проверки кода.
1.4. **Бриф шага:** код собирает агенту контекст — общая выжимка проекта, текст сцены из оригинала, карточки героев, мест и реквизита этой сцены (по сущностям из библии и каталога), её ассеты, открытые замечания. Целиком документы не грузятся.
1.5. **Вызов роли кодом:** конвейер сам запускает ход нужной роли с её подсказкой, навыками и брифом; результат и записи проверок — в документы.
1.6. **Записки между ролями:** структура (от, кому, сцена, текст, статус: открыта, в работе, закрыта), хранятся в проекте; инструмент агента «написать записку» и «закрыть записку».
1.7. **Эскалация:** не больше 2 кругов «замечание → правка» на предмет, дальше режиссёр, потом пользователь.
Готово, когда: короткий тестовый проект (2 сцены) проходит конвейер ролями; в журнале видно, кто что делал; бриф каждой роли в разы меньше прежнего контекста.

## Этап 2. Правило двух ключей и проверка зрением (synshell-d3)

2.1. **Проверяющий со свежим контекстом:** отдельный ход роли-проверяющего — только оригинал, библия и проверяемая вещь, без рассуждений автора.
2.2. **Скрипт-супервайзер со зрением:**
 - эталоны и варианты: тот ли герой и место, костюм, эпоха, время суток; подходит ли сюжету и библии; ✗ — художнику на переделку;
 - кадры роликов: событие сценария в кадре, лицо видно, реквизит тот, преемственность со прошлой сценой; ✗ — оператору на пересъёмку.
2.3. **Редактор диалогов** (может быть ролью сценариста-проверяющего): язык, род, живость, сила брани.
2.4. Проверка от дешёвого к дорогому: сначала код, потом LLM, потом пользователь на вехах.
Готово, когда: на тестовых картинках с нарочно неверным героем, костюмом или местом проверка ловит ошибку, а на верных — пропускает.

## Этап 3. Интерфейс: чипы ролей, доска, лента (synshell-d3, при нужде — syngui)

3.1. **Чипы ролей** под заголовком чата ИИ: статус (думает, ждёт, готово, замечание); по умолчанию режиссёр; клик — переписка роли, можно говорить с ней напрямую.
3.2. **Лента записок** между ролями — карточки в общей ленте.
3.3. **Доска производства:** таблица «сцены × статусы конвейера» с цветом; клик по клетке — документ, ассеты, замечания, ролики сцены.
3.4. **Вехи согласования** (переключатель в проекте): сценарий, лукбук (все эталоны одной доской), первая сцена.
Чего нет в syngui (таблица-доска, чипы со статусом, анимации) — доделать в syngui.
Готово, когда: снимки окна с чипами, доской и лентой; живой прогон 2 сцен виден на доске.

## Этап 4. Парковка контекста ролей в службе (synaptix-uncensored)

4.1. **Несколько припаркованных сессий KV** в службе: ключ — префикс (хэш токенов); общий префикс проекта + префикс роли; хвост префиллится заново.
4.2. **Где держать:** видеопамять → ОЗУ → диск (по памяти), лимит, вытеснение самых старых.
4.3. **Запрос клиента:** «продолжить с припаркованного префикса» и «припарковать»; совместимость со старыми клиентами.
4.4. **Замер:** время переключения роли с кэшем и без (qwen3.8 uncensored, голова 20–40 тыс. токенов).
Готово, когда: переключение роли — секунды вместо префилла всей головы; вывод совпадает с вычислением без кэша.

## Этап 5. Состав под формат, версии, разбор (synshell-d3)

5.1. **Шаблоны составов:** фильм / мультфильм (полный), клип (без сценариста, монтаж под ритм), рилс, подкаст. Пользователь добавляет или убирает роли.
5.2. **Версии документов и ассетов** с откатом; журнал — сводка версий.
5.3. **Продюсер в коде:** очередь видеокарты, оценка времени, лимиты пересъёмок.
5.4. **Разбор после проекта:** частые замечания проверяющих → предложения общих правил в навыки, только с согласия пользователя.

## Общие правила работ

- Пока идёт текущий прогон: только код и коммиты; редактор и службу не перезапускать, видеокарту не занимать. Установка и живая проверка — после прогона, через окно.
- Навыки — только общие правила, без конкретики.
- После каждого этапа — отчёт пользователю .md («было → стало»), выполненное — из todo в done.
