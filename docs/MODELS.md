# Системные нейросети: synaptixd

synaptixd — системная служба, которая держит нейросети [synaptix](../../synaptix) для всех программ. Программа не
тащит движок и веса в свой процесс, а просит у службы задачу («log-probs CTC для этой записи», «выровнять по MFA»,
«сгенерировать текст»). Служба загружает модель при первом запросе, держит её, пока она нужна, и выгружает
неиспользуемые, когда системе не хватает памяти. Модели лежат в библиотеках — папках на любых дисках.

```
 synspeak ─┐                         ┌─ модель A (NPU)  ─┐
 synsettings ─┤ /run/synaptix/synaptixd.sock │─ модель B (CPU)  ─┤─ synaptix (CPU/CUDA/NPU)
 … ─┘   JSON-строки + memfd (SCM_RIGHTS) └─ модель C (выгружена)┘     └─ synnpu-qnn (CDSP, кэш графов)
```

## Состав

| Что | Где |
|---|---|
| Протокол и клиент (serde + libc, без synaptix) | `crates/synaptixd/src/lib.rs` |
| Демон (фича `daemon`, тянет synaptix) | `crates/synaptixd/src/bin/synaptixd/` |
| Юнит systemd | `crates/synaptixd/data/synaptixd.service` |
| Раздел «Параметры → Нейросети» (меню → «По умолчанию», «Служба», страница каждой модели) | `crates/synsettings/src/pages/models.rs` |
| Схема параметров моделей | `synaptix/crates/synaptix/src/facade/params.rs` |
| Распознавание моделей по файлам | `synaptix/crates/synaptix/src/facade/catalog.rs` |
| Библиотеки моделей (обход папок) | `crates/synaptixd/src/bin/synaptixd/library.rs` |

## Модели в системе

Модели лежат только в библиотеках — обычных папках (список и основная — в `/var/lib/synaptix/state.toml`, правит
«Параметры → Нейросети → Хранилище моделей» или `synaptixctl library-add <папка>`). Внутри — папки категорий:

```
<библиотека>/llm/gemma-4-e4b-it.syn             языковые
<библиотека>/image/flux.2-klein-4b.syn          картинки
<библиотека>/video/ltx-2.3-22b-dev.syn          видео (+ части: ltx-gemma-3-12b-qat.syn, апскейлер, IC-LoRA)
<библиотека>/music/  tts/  asr/  embed/
<библиотека>/pronunciation/w2v2-kk/model.toml   модель со своим описанием и файлами весов
<библиотека>/_телефон/ …                        папки на «_» и «.» служба пропускает
```

Файл `.syn` служба узнаёт сама (`synaptix::facade::catalog`: архитектура в бандле + имя) и собирает модель из частей
— LTX-2.3 dev и distilled ссылаются на один файл энкодера Gemma 3 12B, апскейлера и IC-LoRA, ACE-Step — на общие LM
и VAE, MiniMax H3 — на энкодер Qwen3-VL, YuE — на VAE. Модели, которые synaptix по файлу не узнаёт (wav2vec2, MFA,
варианты весов под NPU), лежат подпапкой с `model.toml`. Положил файл — после «Обновить список» модель появилась;
удаление в «Параметрах» стирает файлы модели, не нужные другим моделям. Ссылок и скрытых хранилищ нет — папку можно
разбирать обычным проводником. На ноутбуке библиотека — `~/Storage/Нейросети/Модели`, на телефоне —
`/var/lib/synaptix/library` (папки категорий создаёт synport). Графы NPU лежат в кэше демона `synnpu-qnn`
(`/var/cache/synnpu/*.bin`). `model_dirs` в `/etc/synaptix/synaptixd.toml` — необязательные каталоги вне библиотек.

### model.toml

```toml
id = "w2v2-lv60-espeak"
title = "wav2vec2 LV-60 (фонемы IPA)"
kind = "ctc"                 # ctc | mfa | asr | llm | tts | embed | image | video | music
arch = "wav2vec2"
languages = ["en"]
license = "Apache-2.0"
description = "Фонемное распознавание (eSpeak IPA) для оценки произношения"

[[variant]]                  # первый подходящий по устройству
file = "model-npu.syn"
devices = ["npu"]
precision = "w8a16"          # веса int8 по каналу, счёт F16

[[variant]]
file = "model.syn"
devices = ["cpu", "cuda", "npu"]
precision = "f16"

[resources]                  # оценка для планировщика памяти, МБ
ram = { cpu = 1300, cuda = 200, npu = 700 }
vram = { cuda = 700 }

[defaults]                   # необязательно: поправки к встроенным оптимальным параметрам (ниже)
temperature = 0.8
```

## Устройство и параметры модели

Тип выполнения задаётся для каждой модели: `auto`, `npu`, `cpu`, `cuda`, `gpu`. `auto` — первое доступное по
порядку CUDA → NPU → CPU (из тех, что перечислены в вариантах модели). Недоступные на этой машине устройства
показываются неактивными. `gpu` (Vulkan/wgpu) в synaptix пока заглушка — пункт виден, но выключен.

Если модель упала на выбранном устройстве при загрузке или исполнении (типично — NPU), служба повторяет задачу на
CPU и помечает модель `fallback` до смены устройства; в «Параметрах» это видно.

Параметры (пишутся службой в `/var/lib/synaptix/state.toml`, меняют root и группа `wheel`):

| Параметр | Что |
|---|---|
| `device` | тип выполнения |
| `pinned` | не выгружать при нехватке памяти |
| `idle_unload` | выгрузить после N минут простоя (0 — только при нехватке) |
| `preload` | загружать при старте службы |

Общие настройки — `/etc/synaptix/synaptixd.toml`:

```toml
min_available_mb = 1024   # держать свободным; меньше — выгружать неиспользуемые
idle_unload_min = 10      # по умолчанию для моделей без своего значения
max_loaded = 0            # 0 — без ограничения числа
```

## Параметры модели и модели по умолчанию

Какие параметры есть у модели, решает synaptix: `synaptix::facade::params::param_schema(task, arch, id, path)`
возвращает схему — ключ, подпись, подсказку, тип (`text`, `int`, `float`, `bool`, `choice`), пределы и значение по
умолчанию (`None` — решает модель, «авто»). Схема своя у каждого семейства и у каждой модели:

- LLM — сэмплинг по умолчанию из карточки и `generation_config.json` (`sampling_profile`; Gemma 4 — 1.0 / 0.95 /
  top-k 64), «Размышления», если chat-шаблон знает `enable_thinking`, «Глубина размышлений» с уровнями из шаблона
  (Qwen3.8, Muse Glimmer);
- FLUX — без негативного промпта, SDXL — с ним; LTX-2.3 — без шагов (дистиллированное расписание), FPS выбором;
  ACE-Step — шаги и CFG по варианту (turbo 8 / base 32 / sft 50); OmniVoice — язык, голос, скорость, шаги, CFG.

Служба отдаёт схему в `ModelEntry.schema`, оптимальные значения — в `defaults` (схема + стартовый промпт службы +
`[defaults]` из `model.toml`). Параметры — словарь `ключ → значение` (`Params`); значение берётся по слоям, верхний
побеждает: оптимальные → свои (`settings.params`, «Параметры → Нейросети → модель», `synaptixctl set <id>
param.temperature=0.3`, `=default` — убрать) → запрос (`params` в `generate`/`speak`). Свои и запросные значения
служба сверяет со схемой: неизвестные ключи отбрасываются, числа зажимаются в пределы, варианты — только из списка.
«Параметры» рисуют форму по схеме, поэтому новый параметр модели появляется без правок оболочки.

Стартовый промпт подставляется, только если в `messages` нет своего `system`. `seed = -1` — случайное.

**Квантование** (`settings.quant`): `auto` — оптимальное для устройства. У LLM — политика движка при загрузке:
`auto` = `optimal_profile_for_device` (CPU/NPU — SQ4, CUDA — NVFP4/SQ4 по карте), `int8` — веса и голова SQ8,
`bf16` — без квантования (только CUDA). У остальных — выбор `[[variant]]` по `precision`. Смена перезагружает модель.

**Модели по умолчанию** — по видам (`llm`, `image`, `video`, `music`, `tts`, `asr`, `embed`), в `state.toml`
`[defaults]`. Не выбрана — «авто»: загруженная, иначе с лучшим доступным устройством (CUDA → NPU → CPU).
Программа передаёт `model: ""` (или `"auto"`) — служба берёт модель по умолчанию для вида запроса
(`generate` → llm, `speak` → tts, `transcribe` → asr). `synaptixctl defaults`, `synaptixctl default llm <id|auto>`,
`synaptixctl params <id>`, `synaptixctl gen - текст`.

Виды `image`/`video`/`music` уже есть в протоколе, «Параметрах» и выборе по умолчанию, но исполнители (из synthos)
служба ещё не получила — у таких моделей `runnable = false`.

```rust
let mut c = synaptixd::Client::connect()?;
let over = synaptixd::Params::new().with("temperature", 0.2);
c.generate_with("", messages, &over, |t| print!("{t}"))?;   // модель и прочие параметры — системные
let chat = c.resolve(synaptixd::ModelKind::Llm)?;              // какая модель сейчас по умолчанию, её effective()
```

## Память и выгрузка

Модель «используется», пока она выполняет задачу или открыта клиентом (`open` держит аренду до закрытия соединения).
Перед загрузкой служба оценивает нужное (`resources` из `model.toml`, иначе по файлу весов: F16 на CPU — ×2,
int8 на CPU — 55 % файла, потому что веса читаются через mmap и их страницы система вытесняет сама; Gemma 4 E2B —
2,7 ГБ своей памяти при файле 5,4 ГБ) и, пока
`MemAvailable − нужное < min_available_mb`, выгружает модели в порядке:

1. не открытые никем, по давности последнего запроса;
2. открытые, но простаивающие, по давности (клиент при следующем запросе дождётся повторной загрузки);
3. закреплённые (`pinned`) не выгружаются никогда — если места всё равно нет, загрузка отклоняется с ошибкой
   `no_memory`.

Раз в 5 с служба смотрит `MemAvailable` и `/proc/pressure/memory` и выгружает по тому же порядку, если память
кончается из-за других программ. Простаивающие дольше `idle_unload` выгружаются по таймеру.

На NPU отдельный бюджет — контексты в PD CDSP (~1,8 ГБ на PD у v69): synaptix сам вытесняет давние графы
(`SYNAPTIX_NPU_RESIDENT_MB`); служба одна держит соединение с `synnpu-qnn`, поэтому графы всех программ
живут в одном процессе и не дублируются.

## Протокол

Unix-сокет `/run/synaptix/synaptixd.sock` (`0666`; изменение параметров — только root и `wheel` по
`SO_PEERCRED`). Каждое сообщение — строка JSON; большие данные (PCM, тензоры) — в memfd, переданных через
`SCM_RIGHTS` вместе со строкой. В JSON на них ссылается индекс `{"fd": 0}`. Ответные memfd запечатаны
(`F_SEAL_WRITE|F_SEAL_SHRINK`), клиент делает `mmap` без копирования.

Запрос: `{"id": 7, "op": "...", ...}`. Ответ: `{"id": 7, "ok": true, ...}` или `{"id": 7, "ok": false,
"error": "...", "code": "no_model"}`. Задачи с потоком (генерация текста) шлют события `{"id": 7, "event":
"token", ...}` и в конце обычный ответ. На одном соединении запросы выполняются по порядку; параллельно —
несколько соединений.

| op | Поля | Ответ |
|---|---|---|
| `hello` | `client` | `version`, `devices` (доступные устройства) |
| `list` | — | `models[]`: id, title, kind, languages, size, state, device, pinned, … |
| `status` | — | память системы, загруженные модели и их потребление |
| `open` | `model` | аренда до закрытия соединения; `info` модели (словарь, размерности, корзины) |
| `load` / `unload` | `model` | загрузить заранее / выгрузить |
| `set` | `model`, `device?`, `pinned?`, `idle_unload?`, `preload?`, `quant?`, `params?` (свои значения целиком) | новые параметры |
| `defaults` | — | `[{kind, model?, resolved?}]` — модели по умолчанию |
| `set_default` | `kind`, `model?` (нет — авто) | то же |
| `resolve` | `kind` | запись модели по умолчанию (`defaults` — оптимальные, `settings.params` — свои) |
| `ctc` | `model`, `pcm` (fd, f32 моно), `sample_rate`, `hidden` | `frames`, `vocab`, `frame_sec`, `logprobs` (fd, f32 `[T×V]`), `hidden` (fd, f32 `[T×D]`), `hidden_dim` |
| `mfa_align` | `model`, `pcm` (fd, f32 16 кГц), `words[]` (варианты фонем с весами), `options` | `phones[]`, `frame_shift` |
| `transcribe` | `model`, `pcm` (fd), `sample_rate`, `language?` | `text`, `segments[]` |
| `speak` | `model`, `text`, `language?`, `instruct?` (описание голоса), `speed?`, `steps?` | `samples`, `sample_rate`, `audio` (fd, f32 моно) |
| `generate` | `model` (`""` — по умолчанию), `messages[]`, `params?`, `max_tokens?`, `temperature?` | события `token`, итог `text`, `tokens` |
| `subscribe` | — | поток событий `model_state` (для «Параметров») |

## Языковые модели (generate)

Служба держит на каждую языковую модель одну KV-сессию (контекст 4096, на NPU 2048): новый запрос считает
заново только ту часть промпта, что разошлась с прошлым (`из кэша N` в журнале). Клиенту выгодно, чтобы начало
промпта не менялось между ходами — системный промпт стабилен, история только дописывается; тогда следующий ход
начинает отвечать сразу, а не после префилла всей истории. Прогрев — запрос с тем же системным промптом и
`max_tokens = 1` (synspeak делает его при открытии чата). Gemma 4 E2B на Xiaomi (CPU, int8): префилл ~50 ток/с,
декод ~8 ток/с.

## Встроенный режим

Программа может работать и без службы (ПК без synshell, отладка): у synspeak фича `local` оставляет прежний путь
«synaptix в процессе». Порядок: служба доступна → через неё; иначе, если собрано с `local`, — модель в процессе;
иначе ошибка «служба нейросетей недоступна».

## Int8 на NPU

HTP v69 исполняет FullyConnected с F16-активациями и весами int8 с поканальными шкалами (см.
`synaptix/docs/npu.md`). Для моделей NPU готовится `model-npu.syn`: веса линейных слоёв — int8 по выходному
каналу, шкала подбирается поиском порога отсечения, минимизирующего ошибку восстановления (MSE) на строке,
остальные тензоры — F16. Качество проверяется против F16 на тестовом наборе модели (PER для CTC, WER для ASR,
перплексия для LLM) перед тем, как модель попадёт в библиотеку.

## synspeak

Первый потребитель службы: оценка произношения (`ctc`, `mfa_align`), наставник Фоня на языковой модели (`generate`,
потоковый ответ; фразы для тренировки — строки с «>», их можно прослушать и сразу потренировать с оценкой) и
синтез речи OmniVoice (`speak`): озвучка ответов (пояснения по-русски, фразы — голосом изучаемого языка) и эталоны
для своих фраз и фраз наставника, у которых нет записи. Синтез кэшируется в `~/.local/share/synspeak/tts-cache`.
Модели выбираются в настройках synspeak («AI-наставник»), устройство — в «Параметры → Нейросети».

## Синтез речи (OmniVoice)

`speak` — OmniVoice: текст → волна 24 кГц, язык (`ru`, `en`, `kk`, …), голос по описанию (`instruct`). Число шагов
маскированного декода — `steps` (по умолчанию 16 на NPU, 32 на остальных). На Xiaomi бэкбон идёт на NPU в int8,
кодек — на CPU: фраза 3,5 с синтезируется примерно за 7 с. Проверка: `LANG_CODE=ru synaptixctl say omnivoice out.wav
Текст` (`TTS_STEPS=32` — больше шагов).
