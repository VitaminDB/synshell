# Заметки в synshell: syn-notes

План переноса заметок из synthos (`synthos/src/pages/notes`, ≈27 тыс. строк,
и инструмент агента `src/agent/tools/notes`, ≈8,6 тыс.) в synshell. Функции
переносятся полностью: страницы, канбан, Гант, mindmap, календарь, графики,
журнал, вложения, напоминания, инструмент агента. Появляются интеграции с
системой: ассистент, рабочий стол, системные уведомления, автономный режим.

## Решения (2026-10-19)

- **Формат данных не меняется.** Проект — один файл `.syn` (synaptix-bundle,
  `purpose = "notes"`, `arch = "synthos-notes"`). По умолчанию это
  `~/Documents/SynthOS Notes.syn`, существующий проект synthos открывается
  как есть.
- **Один хозяин данных** — процесс `syn-notes`. Он стартует с сеансом
  (XDG autostart, single-instance) и живёт с тем же окном, только скрытым:
  окно открывается по запросу и при закрытии прячется. Очередь записи
  (`BundleEditor`, автосохранение) живёт только у него, поэтому два процесса
  никогда не пишут один файл.
- **Остальные — клиенты по сокету** `$XDG_RUNTIME_DIR/syn-notes.sock`
  (JSON, строка-запрос → строка-ответ):
  - ассистент (инструмент `notes`) — те же действия и схема, что у
    инструмента synthos; исполняет их хозяин в живом состоянии, так что
    правки агента сразу видны в открытом редакторе и отменяются через Ctrl+Z;
  - рабочий стол — данные виджетов (повестка, карточки, страница);
  - `syn-notes open <страница>`, `synwm msg action shell notes …`.
  Если хозяин не запущен, клиент запускает `syn-notes --background` и ждёт
  сокет.
- **Код один на двоих.** `syn-notes` — библиотека и бинарь. На последнем
  этапе synthos подключает библиотеку вместо `src/pages/notes` и своего
  инструмента; две копии не держим.
- **Протокол отдельно.** Все, кому нужны данные заметок, и так подключают
  syngui (syn-notes) или ходят через сокет (оболочка, ассистент), поэтому
  модель осталась модулями библиотеки `syn-notes`. Клиентам — лёгкий крейт
  `syn-notes-proto`: схема инструмента `notes`, путь сокета, запросы,
  запуск хозяина в фоне.
- **Один проект — один процесс.** Открывая `.syn`, процесс берёт `flock`
  на файле в `$XDG_RUNTIME_DIR/notes-locks/` (имя — хэш пути; сам `.syn`
  уплотнение подменяет). Пока synthos не на библиотеке, работающий synthos
  с открытым проектом тоже считается хозяином. Занятые при старте проекты
  syn-notes помнит и раз в минуту пробует открыть снова.

## Состав

| Крейт | Что |
|---|---|
| `syn-notes` (lib) | `notes` — перенесённый код synthos (формат `.syn`, страницы, kanban/gantt/mindmap/calendar/chart, журнал, напоминания, автосохранение, интерфейс), `tool` — инструмент `notes`, `app` — окно, сокет, сводка для стола |
| `syn-notes-proto` | схема и описание инструмента, сокет, клиент (`tool`, `open`, `desk`, `ensure_running`) |
| `syn-notes` (bin) | окно, `--background`, `open`, `--screenshot` |
| `synassist` | `NotesTool` — клиент сокета, раздел промпта, режим в Параметрах |
| `synshell-ui` | виджеты из заметок, переключатель «виджеты / заметки», автономный режим ассистента |
| `synshell-common` | `[notes]` и `[assistant.autonomy]` в конфиге, протокол сокета заметок, `Request::Idle` в IPC synwm |

## Уведомления

Хозяин считает напоминания тем же кодом, что synthos: просроченные карточки
(каждый день), срок сегодня/завтра, события за N минут. Вместо тостов в окне —
`org.freedesktop.Notifications` с кнопками «Открыть», «Готово» (закрыть
карточку), «Отложить на час». Ответ приходит сигналом `ActionInvoked`.
Колокольчик со сводкой остаётся в приложении. Повторно одно и то же не
показывается — `ReminderState.fired` в проекте, как сейчас.

## Рабочий стол

- Новые типы виджетов: `notes-agenda` (сегодня/просрочено), `notes-board`
  (колонка канбана), `notes-page` (страница или её часть), `notes-calendar`.
  Данные берутся из сокета, тап открывает страницу в syn-notes.
- Внизу слева переключатель «Виджеты / Заметки». Режим «Заметки» показывает
  страницу проекта, назначенную рабочим столом (по умолчанию «Рабочий стол»).
  Её блоки в свободной раскладке и есть виджеты стола. Правка страницы —
  в syn-notes.

## Настройки

- `[notes] storage` — основное хранилище (проект `.syn`), тот, с которым
  работают ассистент, виджеты и напоминания. Меняется в самом syn-notes
  (Настройки → Хранилище) и в Параметрах → Заметки.
- `[notes] reminders`, `desk_page` — напоминания и страница рабочего стола
  (Параметры → Ассистент → «Заметки»).

## Автономный режим ассистента

Выключен по умолчанию. `[assistant.autonomy]`:

```toml
enabled = false
interval_min = 10        # как часто просыпаться
idle_min = 5             # пользователь не трогал ввод столько минут
max_gpu_percent = 20     # загрузка ГПУ выше — пропустить такт
busy_apps = ["steam", "obs"]   # пока запущены — не работать
board = "Ассистент"      # доска задач ассистента в основном хранилище
ask = "new"              # always | new | never — спрашивать ли «выполнить?»
```

Карточка с меткой `не-делать` пропускается («Не делать» в уведомлении её
ставит); «Не сейчас» откладывает задачу на 20 часов, неудача — на сутки.
Отметки — `~/.local/state/synassist/autonomy.json`.

- Планировщик живёт в оболочке (`synshell-ui`): она идёт весь сеанс, у неё
  есть агент и уведомления с кнопками.
- Такт: таймер → проверки простоя (synwm `Request::Idle`), загрузки ГПУ
  (`synsystem::gpu`), занятости службы (`synaptixd` `metrics().running`) и
  запущенных программ → открытые карточки доски «Ассистент» со сроком ≤
  сейчас (или без срока) → для каждой, если нужно, уведомление «Выполнить
  „…“?» (Да / Нет / Позже) → агент с подписью службы «автономный режим»,
  инструменты с `Danger::Confirm` спрашиваются уведомлением → итог пишется
  в карточку (комментарий + ссылка на чат), карточка уходит в «Готово»,
  повторяющиеся порождают следующую.
- Любой ввод пользователя во время работы не прерывает задачу, но новые
  такты ждут простоя.

## Этапы

1. ✅ syngui: `start_hidden`, `hide_on_close`, `show_main_window` из любого
   потока; поток перетаскивания Wayland больше не держит окно.
2. ✅ `syn-notes`: код заметок synthos целиком (190 тестов), замены
   зависимостей synthos (состояние — `~/.local/state/syn-notes/state.json`,
   при первом запуске — из конфига synthos), тема из палитры synshell,
   переводы на 14 языков, панель проектов.
3. ✅ Хозяин: `--background` (автозапуск), сокет, `syn-notes open …`.
4. ✅ Инструмент `notes` у ассистента (пул `autotools`), режим в Параметрах.
5. ✅ Напоминания → системные уведомления с кнопками.
6. ✅ Рабочий стол: виджеты `notes-agenda`, `notes-board`, `notes-page`,
   вид «Заметки» с переключателем внизу слева (`[desktop] view`).
7. ✅ Автономный режим (`synshell-ui/src/autonomy.rs`), простой — запрос
   `Idle` композитора (`synwm msg idle`), настройки в Параметрах → Ассистент.
8. ✅ synthos на библиотеке `syn-notes` (0.2.315): свои копии режима и
   инструмента удалены, `crate::pages::notes` — реэкспорт библиотеки, связи
   — `synthos/src/notes_host.rs` (состояние в конфиге synthos, навигация и
   плитки рейла, вложения чатов, кнопка поиска в шапке), бюджет контекста
   общий, каталоги строк заметок — из библиотеки.
