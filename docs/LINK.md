# Связь устройств (`synlink`)

Две оболочки synshell — телефон и компьютер — находят друг друга по кабелю
USB и в одной сети Wi-Fi и дают друг другу:

- **экран**: трансляция с управлением (`synlink-view`), снимки;
- **ввод**: мышь, касания, клавиши и текст на другом устройстве;
- **файлы**: файловая система устройства в Проводнике → «Устройства»;
- **уведомления**: уведомления одного устройства показываются на другом;
- **ssh**: `ssh phone` / `ssh <имя>` без знания адреса — по USB или Wi-Fi;
- **отладку**: CLI `synlink` и MCP-сервер для Claude Code — снимок экрана,
  касания, набор текста, команды, журнал systemd.

Телефон, пока подключён кабелем, показывает в шторке «Кабель USB подключён ·
оболочки соединены» и карточку компьютера; при соединении/разрыве —
всплывающее сообщение.

## Устройство

```
 ┌─────────── компьютер ───────────┐            ┌──────────── телефон ─────────────┐
 │ synwm ─IPC─ synlink daemon ──────┼── QUIC ────┼── synlink daemon ─IPC─ synwm      │
 │  (кадры,   │  │ локальный сокет  │ USB (NCM)  │   │  FUSE ↔ файлы    (кадры, ввод) │
 │   ввод)    │  └─ оболочка, synlink-view,      │   └─ оболочка (шторка, диалог)    │
 │            │     Параметры, Проводник, CLI,   │                                  │
 │            │     MCP                          │                                  │
 └────────────┴─────────────────────────────────┘ или Wi-Fi └──────────────────────┘
```

| Часть | Где | Что делает |
|---|---|---|
| `synlink daemon` | `crates/synlink` | поиск, соединения, спаривание, вызовы, FUSE, уведомления, ssh |
| протокол для программ | `synshell_common::link` | JSON-строки по `$XDG_RUNTIME_DIR/synlink.sock` |
| `synlink` (CLI), `synlink mcp` | `crates/synlink` | команды и MCP-сервер поверх локального сокета |
| `synlink-view` | `crates/synlink-view` | окно трансляции (виджет syngui `LiveView`) |
| оболочка | `synshell-ui/src/link.rs` | апплет `link`, окно «Устройства», шторка, диалог спаривания |
| композитор | `synwm/src/remote.rs`, `stream.rs` | удалённый ввод и поток кадров (IPC `input`, `frame-stream`) |

Демон запускается сеансом (`/etc/xdg/autostart/synlink.desktop`), по одному на
пользователя; настройки — `[link]` в `config.toml`, меняются на лету
(«Параметры → Связь с устройствами»).

### Поиск и транспорт

- Анонсы UDP (порт `[link] port − 1`, по умолчанию 47470) на широковещательный
  адрес **каждого** интерфейса, и Wi-Fi, и USB-сети телефона (NCM,
  `172.16.42.1 ↔ .2`); по USB ещё и напрямую соседу. Чем устройство достижимо,
  решает подсеть адреса: интерфейс, чьё устройство в sysfs на шине USB (хост) или
  функция гаджета (телефон), — это USB.
- Соединение — QUIC (quinn) на UDP 47471: TLS 1.3, независимые потоки (копирование
  файлов не тормозит кадры экрана), keep-alive 3 с, разрыв за 12 с.
- Соединение начинает устройство с меньшим id; по USB и Wi-Fi одновременно
  остаётся одно — по USB (появился кабель — сеанс переезжает на него).
- Сами соединяемся только со спаренными и с устройствами на кабеле; чужие в
  Wi-Fi видны как «Рядом», спаривание с ними начинает пользователь.
- Телефон с погашенным экраном спит (флаг `/run/syn-sleep/screen-off` платформы,
  arch-mobile-port docs/20): демон закрывает сеансы по Wi-Fi, не анонсируется и
  входящих по Wi-Fi не принимает — keep-alive QUIC с компьютера будил его каждые
  3 с, а анонс после самопробуждения вёл к новому соединению. Включили экран —
  анонс сразу. По USB (кабель) всё как прежде: с кабелем телефон не спит.

### Личность и спаривание

- Ключ ed25519 и самоподписанный сертификат в `~/.local/share/synlink/`; id
  устройства — начало SHA-256 сертификата. Подпись рукопожатия TLS проверяется,
  доверие — по закреплённому отпечатку (`peers.json`).
- **USB**: компьютер соглашается сразу, телефон спрашивает одно подтверждение
  («Разрешить экран, ввод, файлы, уведомления и ssh?»).
- **Wi-Fi**: код из 6 цифр (хэш обоих отпечатков) показывается на обоих
  экранах; подтверждает принимающая сторона. Машина с `discoverable = false`
  по Wi-Fi не анонсируется и чужих не принимает.
- Диалог показывает оболочка; если её нет — уведомление с кнопками
  «Принять/Отклонить»; из терминала — `synlink pair accept <устр>`.
- При спаривании ключ ssh устройства попадает в `~/.ssh/authorized_keys` с
  пометкой `synlink:<id>`; «Забыть» убирает его с обеих сторон.

### Вызовы

Каждый вызов — отдельный поток QUIC: сообщение `Rpc` (postcard), дальше по виду:

| Вызов | Что |
|---|---|
| `Screenshot` | полный кадр вывода → PNG |
| `Input` | пачка `ipc::InputEvent` композитору |
| `Wm` | любой запрос IPC композитора (окна, выводы, действия) |
| `Exec` | команда: stdin/stdout/stderr или PTY (`synlink shell`) |
| `Tcp` | туннель к `127.0.0.1:порт` (0 — sshd) |
| `Screen` | поток кадров: только изменившиеся прямоугольники, zstd, ≤ 2 кадра в пути (proto 1) |
| `ScreenV2` | то же плюс видео аппаратным кодером той стороны (proto 2, см. «Экран») |
| `Fs` | stat/readdir/read/write/create/rename/… для FUSE |

### Экран

synwm держит для каждого потока свой буфер и `OutputDamageTracker`
(`stream.rs`): кадр дорисовывается только в повреждённых местах, наружу уходят
эти прямоугольники (файл потока в `$XDG_RUNTIME_DIR`, отображён в память; ответ
IPC — их список). Поток тянущий: следующий кадр готовится после подтверждения,
так что медленная сеть снижает частоту, а не копит очередь. Неподвижный экран
не стоит ничего.

**Видео** (`[link] screen_codec`, «Параметры → Связь с устройствами →
Трансляция экрана»). Если у транслирующей стороны GPU-композитор и аппаратный
кодер V4L2 (телефон: msm_vidc), крупные изменения идут видеокадром:
- кадр потока (текстура GLES) переводится в NV12 на GPU двумя проходами
  шейдера (Y → R8, UV → GR88 вдвое меньше) **прямо в dma-buf кодера**
  (`encode.rs`, `v4l2enc.c`) — без копий через CPU; BT.709, полный диапазон;
- кодер H.264/HEVC, без B-кадров, длинная группа кадров; ключевой кадр — в
  начале и по просьбе зрителя (новый или ошибившийся декодер);
- места, ушедшие видео, **досылаются без потерь**, когда экран замер на 150 мс:
  при движении — плавно и мало трафика, в покое — пиксель в пиксель;
- `auto` — HEVC (нет — H.264), мелкие изменения (< 4 % экрана: курсор, часы,
  набор текста) сразу без потерь; `h264`/`hevc` — видео для всех изменений;
  `lossless` — только zstd. Битрейт `screen_bitrate` (Мбит/с), 0 — по кабелю 80,
  по Wi-Fi 30. Нет кодера или он сломался — поток сам уходит в без потерь.
- поворот экрана (другой размер вывода) — новый кодер; окно зрителя меняет
  ширину и высоту местами.

Протокол: вызов `ScreenV2` (proto 2; со старыми устройствами — прежний
`Screen`), кадр — прямоугольники zstd + видеопакет, подтверждение с просьбой
ключевого кадра. В пути ≤ 2 кадров без потерь или ≤ 6 маленьких видеокадров
(иначе на Wi-Fi частоту ограничивает время ответа).

`synlink-view` декодирует видео libavcodec (загружается `dlopen`, ffmpeg для
сборки не нужен; нет — просит поток без потерь), YUV → RGB сам в нескольких
потоках и только в изменившихся местах, потом накладывает прямоугольники без
потерь и отдаёт кадр виджету `LiveView` (syngui). `SYNLINK_VIEW_TIMING=1` —
время декодирования и перевода цвета в stderr.

Замер (Redmi K50 Ultra → ноутбук по Wi-Fi, vkcube на весь экран 1220×2712,
поток до зрителя; зритель успевает ≈ 7 мс на кадр):

| Режим | Кадров/с | Трафик |
|---|---|---|
| без потерь (zstd) | 27 | 3,8 МБ/с |
| H.264 | 71 | 0,5 МБ/с |
| HEVC (`auto`) | 96 | 0,5 МБ/с |

Ввод: на телефон — мышь как палец (правая кнопка — «назад», средняя —
«домой»), на компьютер — мышь, касания как мышь; печатные символы уходят
текстом (раскладку выбирает та сторона — synwm временно переключает группу
xkb), сочетания и спецклавиши — кодами evdev.

### Файлы

FUSE (`fuser`, монтирует `fusermount3` — пакет `fuse3`) в
`$XDG_RUNTIME_DIR/synlink/<имя устройства>`: корень — `/` устройства, права —
пользователя его демона, владелец «своих» файлов показывается как локальный
пользователь. Проводник показывает устройство в «Устройствах» и открывает его
домашний каталог. Смена USB ↔ Wi-Fi монтирование не рвёт.

### ssh

`~/.local/share/synlink/ssh/config` (подключён строкой `Include` в начале
`~/.ssh/config`) — для каждого спаренного: `Host <имя> <id>.synlink phone`,
`ProxyCommand synlink proxy <id>`, свой ключ и known_hosts (ключ хоста приходит
при соединении). Туннель идёт внутри соединения synlink, поэтому `ssh phone`
работает и по кабелю, и по Wi-Fi. Если системный sshd не запущен (компьютер
без sudo), демон поднимает sshd пользователя на `127.0.0.1:22022` — снаружи
его не видно.

### Уведомления

Сервер уведомлений — сама оболочка; демон видит их мониторингом шины сеанса
(`BecomeMonitor` на `Notify`) и пересылает спаренным, пришедшие — показывает
через обычный `Notify` (приложение «<программа> · <устройство>»). Пересланные
помечены подсказкой `x-synlink-device` и обратно не уходят; мгновенные
(громкость, яркость) не пересылаются.

## Командная строка

```
synlink status                 # эта машина, кабель, устройства
synlink shot phone -o a.png    # снимок экрана (PNG)
synlink tap phone 540 1200     # касание (пиксели снимка или доли 0..1)
synlink swipe phone 0.9 0.5 0.1 0.5 300
synlink type phone 'привет'    # текст в поле с фокусом
synlink key phone ctrl+a       # сочетание
synlink action phone back      # действие synwm: back, shell home, shell shade…
synlink exec phone -- uname -a # команда (вывод потоком, код выхода)
synlink shell phone            # терминал
synlink logs phone -f -u synshell
synlink windows phone          # окна (JSON)
synlink view phone             # окно трансляции
synlink mount phone            # файлы (обычно смонтированы сами)
ssh phone                      # ssh внутри соединения
```

Устройство — имя, начало id, `phone`/`desktop`/`laptop` (если такое одно) или
`local` — эта машина (снимки, ввод и команды без сети: удобно отлаживать
оболочку на самом компьютере).

## Claude Code (MCP)

```
claude mcp add synlink -- synlink mcp
```

Инструменты: `devices`, `screenshot` (картинка, по умолчанию длинная сторона
1280 px), `tap`, `long_press`, `swipe`, `scroll`, `type_text`, `key`, `action`,
`windows`, `exec`, `logs`, `notifications`, `read_file`, `write_file`.
Координаты жестов — в пикселях последнего снимка этого устройства (пересчёт
в экран делается сам).

## Настройки `[link]`

```toml
[link]
enabled = true        # демон в сеансе
name = ""             # имя для других (пусто — модель устройства)
discoverable = true   # видна в Wi-Fi для спаривания
notifications = true  # пересылать и показывать уведомления
auto_mount = true     # файлы соединённых устройств — в Проводник
port = 47471          # UDP QUIC; поиск — port − 1
```
