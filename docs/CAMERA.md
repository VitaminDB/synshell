# Камера (`syncamera`)

Программа «Камера» synshell для телефона: по возможностям — как камера Google Pixel, внешне — тоже.
Кадры, снимки и управление даёт служба камеры платформы **syncamd** (arch-mobile-port,
`camera/syncam.h`, протокол v3, docs/22-camera.md): сокет `/run/syncam/syncam.sock`, группа `video`.

```
syncamera                       # SYNCAMERA_TIMING=1 — время пересчёта превью и копии в кодер, в stderr
SYNCAMERA_DEMO_QR=текст syncamera   # вид подсказки QR без камеры (отладка на компьютере)
```

## Где лежит снятое

- снимки — `IMG_ГГГГММДД_ЧЧММСС.jpg` в каталоге «Изображения» (`XDG_PICTURES_DIR` из `~/.config/user-dirs.dirs`);
- видео — `VID_ГГГГММДД_ЧЧММСС.mp4` в «Видео» (`XDG_VIDEOS_DIR`);
- миниатюры (кадр превью в момент съёмки) — `~/.cache/syncamera/<имя>.png`;
- настройки — `~/.config/syncamera.conf`; «Полноэкранный режим» — окно во весь экран (без заголовка и панели состояния), с запасом 32 px под вырез экрана: сверху в портрете, в альбомном — с той стороны, где верх телефона (по акселерометру).

Папки меняются в настройках («Хранение» → «Изменить»): окно выбора папки системного портала
(`org.freedesktop.portal.FileChooser`, в synshell — Проводник, `portal.rs`); папка проверяется на запись,
«По умолчанию» — снова XDG.

## Возможности

- **Режимы** (смахивание по кадру вбок или по названию): Ночь · Профи · Фото · Видео · Таймлапс.
- **Фото**: вспышка (выкл./авто/вкл.), таймер 3/10 с (касание кадра — отмена), сетка третей, 4:3/16:9/1:1,
  полное разрешение (основная 200 Мп, фронтальная 20 Мп; ремозаика Quad-CFA ≈ 12–15 с). Поток JPEG
  настраивается вместе с превью — снимок без перенастройки камеры. Ориентация телефона (акселерометр,
  iio-sensor-proxy) — в EXIF.
- **Ночь**: серия 5–10 кадров YUV полного размера (4096×3072) с потока → выравнивание сдвигом (пирамида
  яркости 1/8 → 1/2), слияние с отбраковкой несовпавших пикселей (движение не «двоится»), тоновая кривая
  тёмной сцены, JPEG кодером MJPEG FFmpeg с EXIF (`night.rs`). Плюс сцена NIGHT самого HAL.
- **Профи**: ISO (логарифмическая шкала), выдержка (1/8000…4″ в пределах датчика), ручной фокус (диоптрии,
  если есть автофокус), баланс белого (авто, лампа, флуоресцент, день, облачно), EV; в автоматике —
  текущие ISO и выдержка из метаданных камеры.
- **Видео**: 720p/1080p/4K 30 к/с, H.264 или HEVC — аппаратный кодер V4L2 (msm_vidc, `venc.c`, очередь
  кадров), звук AAC с микрофона (cpal → PipeWire), MP4 (libavformat). Кадры пишутся как их отдаёт датчик,
  ориентация — матрицей отображения MP4 (`tkhd`), как у камер телефонов. Пауза, снимок во время записи
  (поток JPEG 16:9 рядом с видео до 1080p), фонарик, цифровая стабилизация (EIS HAL).
- **Таймлапс**: каждый 5/10/30/60-й кадр, 30 к/с, без звука.
- **Зум**: кнопки ,6 / 1 / 2 / 5 и щипок (до 10×, область кадрирования HAL); 0,6× — широкоугольная камера
  (переход на другой объектив — по окончании щипка или кнопкой).
- **Касание кадра** — фокус и экспозиция по точке (кольцо желтеет, когда фокус наведён) и ползунок яркости;
  удержание — блокировка AE/AF. Без касаний 6 с — снова автоматика.
- **QR-коды** в «Фото»: уменьшенная яркость кадра раз в ~0,3 с — фоновому потоку (rqrr); подсказка над низом
  кадра с текстом, «открыть» (ссылка — xdg-open) и «копировать» (wl-copy); гаснет через 3 с без кода.
- **Подсказка «Ночь»**: в «Фото» при ISO ≥ 1600 и выдержке ≥ 1/30 — касание включает «Ночь».
- **Выбор задней камеры** — выпадающий список над кадром: основная (200 Мп, 1×), широкоугольная (0,6×), макро.
  Исправность — по пробе платформы `/run/camera/status.json` (`modules.rs`): неисправный модуль показан серым с
  причиной («датчик не отвечает») и не выбирается. «Камера при запуске» (основная, широкая, фронтальная,
  последняя) — в настройках.
- **Смена камеры** (задняя/фронтальная; превью фронтальной зеркальное, снимки и видео — нет).
- **Просмотр снятого** (миниатюра слева от затвора): снимки с масштабом пальцами, видео с перемоткой,
  листание, сведения о файле, «открыть в…», удаление с подтверждением. Камера на время просмотра выключается.
- Звуки затвора и записи (синтез), вибрация (`[haptics]`), альбомное окно — панели справа.

## Устройство

| Модуль | Что делает |
|---|---|
| `proto.rs` | протокол syncamd v3: HELLO/CAMERAS, OPEN (флаги VIDEO/META, поток JPEG), FRAME/RELEASE, CONTROL, META, SNAPSHOT |
| `engine.rs` | сеанс: поток кадров в фоне, превью (`LiveFrame`), серия кадров для «Ночи», запись; повтор, если камера занята |
| `convert.rs` | NV21 → RGBA с поворотом, зеркалом и прореживанием (превью ≤ 2,2 Мп), NV21 → NV12 для кодера |
| `recorder.rs`, `venc.c` | кодер V4L2 (вход — dma-heap, копия CPU), AAC, MP4 с матрицей поворота |
| `night.rs` | слияние серии, тоновая кривая, JPEG + EXIF |
| `media.rs` | каталоги XDG, имена, список снятого, миниатюры |
| `orientation.rs` | ориентация телефона (iio-sensor-proxy) |
| `modules.rs` | задние модули и их исправность по пробе платформы |
| `ui.rs`, `viewer.rs` | экран камеры, настройки, просмотр |

Поворот превью: задняя — поворот датчика + поворот окна, фронтальная — датчик − поворот окна и зеркало.
Точка касания переводится обратно в доли кадра потока (`to_stream`), syncamd — в координаты активной
области матрицы с учётом зума.

## Не сделано

- Портрет (размытие фона), панорама, замедленная съёмка (нужны сеансы высокой частоты HAL).
- Многокадровое HDR в обычном «Фото» (механизм серии из «Ночи» подходит).
- Затвор кнопками громкости (их забирает композитор — громкость), геометка.
- Альбомная раскладка проверена поворотом экрана композитором (`rotate 90`), не поворотом телефона: направление
  поворота превью в альбомном окне по акселерометру (left-up = 90° по часовой) стоит проверить в руках.
