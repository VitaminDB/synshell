# synnetd — несколько подключений к интернету

Служба позволяет пользоваться несколькими подключениями сразу: Wi-Fi,
кабелем, телефоном в режиме USB-модема, мобильной сетью. Настройки — в
«Параметрах» → «Подключения к интернету».

```sh
sudo systemctl enable --now synnetd
```

## Режимы

- **Только основной канал** (по умолчанию) — весь трафик идёт через один
  канал, остальные запасные: отключился основной — всё переходит на
  оставшийся. Основной выбирается автоматически (меньшая метрика маршрута:
  кабель, затем Wi-Fi, затем USB-модем) или вручную.
- **Все каналы сразу** — маршрут по умолчанию через все каналы (multipath):
  разные соединения расходятся по разным каналам по хешу адресов и портов.
  Загрузки из многих источников (торренты, обновления, Steam) используют все
  каналы; одно соединение всегда идёт через один канал.

Для **каждой программы** можно выбрать своё — «Только основной канал», «Все
каналы сразу» или **конкретный канал** («Только USB-модем · enp128s20f0u1»,
«Только Wi-Fi · wlan0» — сколько бы модемов ни было) — независимо от общего
режима. Например, торрент-клиент через все каналы или только через модем, а
браузер и звонки — только Wi-Fi. Выбранный канал не подключён — программа
идёт через основной; у канала нет IPv6, а у других есть — IPv6 программе
закрыт (она идёт по IPv4 через свой канал, а не мимо выбора).

## USB-модем

Телефон, подключённый по USB (драйверы `rndis_host`, `cdc_ether`, `cdc_ncm`,
`cdc_eem`, `ipheth`), сам модемом не становится: его подключают и ради
зарядки и файлов, а iPhone с включённым «Режимом модема» начал бы раздавать
интернет. Пока пользователь не решил, служба интерфейс не поднимает и адрес
не берёт; оболочка спрашивает уведомлением — «Подключить как модем» /
«Только зарядка и файлы». Решение запоминается для устройства (ключ —
`vid:pid:серийный` из USB, у iPhone серийный — UDID; без серийного — MAC) и
меняется в Параметрах → «Подключения к интернету» → «Телефоны по USB»
(«Спрашивать при подключении» — спросить снова) или командой
`synnetd usb <ключ> modem|no|ask`.

С решением «модем», если интерфейс никто не настраивает (нет
NetworkManager, systemd-networkd не управляет им, dhcpcd ограничен
`allowinterfaces`), служба поднимает его и через 5 с без адреса включает
свой DHCPv4-клиент на пакетном сокете. Маршрут модема — с метрикой 4000
(ниже приоритетом, чем Wi-Fi dhcpcd), DNS передаётся systemd-resolved. IPv6
ядро настраивает само по объявлениям маршрутизатора. Решение сменилось на
«нет» — адрес и маршрут снимаются, интерфейс опускается (телефон перестаёт
раздавать). Всё сразу выключается переключателем «Поднимать USB-модемы».

## Как устроено

Таблица `main` не меняется никогда: каналы — это маршруты по умолчанию в
`main` (их ставят dhcpcd, iwd, NetworkManager, модем), а служба кладёт своё
в отдельные таблицы и правила с приоритетами 10000–10299. Остановка службы
или сбой оставляют систему как без неё.

| Таблица | Что в ней |
|---|---|
| `2000 + ifindex` | маршрут по умолчанию одного канала |
| 1990 | все каналы (`nexthop` каждого, вес 1) |
| 1991 | основной канал (`unreachable`, если у семейства его нет) |

| Приоритет | Правило |
|---|---|
| 10000 | `lookup main suppress_prefixlength 0` — локальные сети из `main` |
| 10003 / 10004 | программы «только канал X»: таблица канала X (метка — из имени интерфейса) или `unreachable`, если канал подключён без этого семейства адресов |
| 10005 | только если у основного канала нет этого семейства (IPv6 только у модема): закрыть его, чтобы IPv6 не уходил мимо выбора |
| 10010 | `from <адрес канала> lookup <таблица канала>` — пакеты с адресом канала уходят только через него |
| 10100 | метка «только основной» → 1991 |
| 10110 | метка «все каналы» → 1990 |
| 10200 | остальное: 1990 в режиме «все каналы», иначе 1991 |

`net.ipv4/ipv6.fib_multipath_hash_policy = 1` — соединения распределяются по
адресам и портам. Пока подключён один канал, правил нет совсем. Включён VPN
(маршрут по умолчанию через туннель wireguard/tun в любой таблице) — служба
снимает свои правила и не вмешивается.

**Программы.** Процесс программы (и всё, что он запускает) переносится в
под-cgroup своей же cgroup: `…/session-4.scope/synnet-both`. Сеанс logind
(по нему polkit и порталы узнают процесс) остаётся прежним, при выходе из
сеанса процессы завершаются вместе с ним. К под-cgroup прикреплена
BPF-программа `cgroup/sock_create` из четырёх инструкций: она ставит метку
каждому новому сокету IPv4/IPv6, и маршрут выбирается по метке уже при
`connect()` — адрес источника всегда от нужного канала. Перенос — сразу при
`exec` (netlink proc connector) и пересмотром процессов раз в 10 с; сокеты,
открытые за 1–5 мс до переноса, служба помечает сама (`pidfd_getfd` +
`SO_MARK`). Потомок программы идёт по выбору ближайшего предка с правилом;
правило убрали — процессы возвращаются на место и метки снимаются.

Программа узнаётся по имени процесса, имени исполняемого файла, полному пути
или (у интерпретаторов `python3 /usr/bin/deluge`) по имени скрипта.

## Командная строка

```sh
synnetd status                       # состояние (JSON)
synnetd mode primary|both            # основной канал или все сразу
synnetd primary wlan0|auto           # основной канал
synnetd app qbittorrent both         # выбор для программы (primary|both|iface:<канал>|system)
synnetd app firefox iface:wlan0      # только через Wi-Fi
synnetd usb <ключ> modem|no|ask    # телефон по USB: модем, только зарядка, спросить снова
synnetd usb-dhcp on|off
```

Менять настройки могут root и группа `wheel` (сокет `/run/synnetd.sock`,
строка JSON на запрос и ответ). Настройки — `/var/lib/synnetd/config.toml`.
